## 二、每日工作流 / Daily Workflow

```
1. 拉取最新代码 / Pull latest code
   git stash -u → git pull → git stash pop

2. 启动服务 / Start services
   后端 Backend: IDEA 运行 RuoYiApplication / Run in IDEA
   前端 Frontend: cd ruoyi-ui → npm run dev

3. 开发 / Development
   写 Controller → 编译验证 → 接口自测
   Write Controller → Compile → API self-test

4. 提交 / Commit
   Ctrl+K → 只勾业务文件 → commit → Ctrl+Shift+K push
   Ctrl+K → Select only business files → commit → Ctrl+Shift+K push

5. 拉取检查 / Pull & check
   同事推了新代码 → stash → pull --rebase → stash pop → push
   Colleague pushed → stash → pull --rebase → stash pop → push
```

## 三、接口开发标准流程 / Standard API Development Workflow

```
1. 需求分析 / Requirement analysis
   → 确定哪些接口给运营端，哪些给小程序端
     Determine which APIs for ops side, which for client side
   → 确定入参出参
     Define input/output parameters

2. 看 Service 层 / Review Service layer
   → 现有 Service 有哪些方法可复用
     What existing Service methods can be reused
   → 不够的要不要补
     Add new methods if needed

3. 写 Controller / Write Controller
   → 运营端 Ops: /api/v1/ops/* + @PreAuthorize
   → 小程序端 Client: /api/v1/* + @Anonymous
   → 加 @Schema/@Operation 文档 / Add documentation

4. 编译验证 / Compile check
   mvn -pl ruoyi-admin -am compile -q

5. 接口自测 / API self-test
   → 新增 → 查询 → 修改 → 删除 闭环
     Create → Read → Update → Delete loop

6. 提交推送 / Commit & push
   → 只提交业务文件 / Only commit business files
   → commit message 写清楚改了什么 / Clear commit message

7. 通知前端 / Notify frontend developers
   → 发接口地址 + Swagger 链接
     Send API URLs + Swagger link
   → 切 loop-v1 分组 / Switch to loop-v1 group
```
