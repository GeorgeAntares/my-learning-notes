# Git 团队协作实战 / Git Team Collaboration in Practice

## 一、日常协作流程 / Daily Collaboration Workflow

团队开发中，每天都有同事往远程仓库推代码，你需要拉取最新代码再开始工作。

In team development, colleagues push code to the remote repository daily. You need to pull the latest code before starting work.

### 标准拉取流程（stash 三步法）/ Standard Pull Workflow (stash 3-step method)

当你本地有未提交的改动，远程也有新提交时：

When you have uncommitted local changes and the remote also has new commits:

```bash
# 1. 暂存本地改动（临时收起来，不丢）
#    Stash local changes (temporarily save, won't lose)
git stash -u

# 2. 拉取远程代码 / Pull remote code
git pull

# 3. 恢复本地改动 / Restore local changes
git stash pop
```

- `git stash -u`：`-u` 表示连未跟踪的新文件一起暂存 / `-u` includes untracked files
- 执行后工作区变干净，可以安全拉取 / After execution, working directory is clean and safe to pull
- `git stash pop`：把暂存的改动放回来 / Restores stashed changes

### 为什么不能直接 git pull / Why not just git pull directly

如果本地改了文件 A，远程也改了文件 A，直接 `git pull` 会被拒绝：

If both local and remote modified file A, `git pull` will be rejected:

```
error: Your local changes to the following files would be overwritten by merge
```

stash 三步法就是解决这个问题的 / The stash 3-step method solves this problem.

## 二、提交代码 / Committing Code

### 选择性提交 / Selective Committing

团队项目中，不是所有改动都该提交。用 IDEA 的 Commit 面板（Ctrl+K）可以只勾选需要提交的文件：

In team projects, not all changes should be committed. Use IDEA's Commit panel (Ctrl+K) to select only the files that should be committed:

| 该提交 Should commit | 不该提交 Should NOT commit |
|--------|---------|
| 业务代码（Controller、Service）Business code | `.idea/*`（IDE 配置 / IDE config） |
| 前端页面（Vue、JS）Frontend pages | 调试用临时改动（SecurityConfig 放行 / Debug temp changes） |
| SQL 脚本 SQL scripts | `package-lock.json`（锁文件 / Lock file） |
| 配置文件改动 Config changes | 临时文档、PDF Temp docs |

### Commit Message 规范 / Commit Message Convention

```
简短描述（一行）/ Brief description (one line)

- 改动点1 / Change 1
- 改动点2 / Change 2
```

示例 / Example:
```
平台公告增删改查接口及小程序端读取接口
Platform notice CRUD API and mini-program read API

- LoopNoticeController: 运营端公告增删改查5个接口 / 5 ops-side notice CRUD endpoints
- ClientNoticeController: 小程序端公告列表/详情/标记已读3个接口 / 3 client-side notice endpoints
```

## 三、推送被拒绝 / Push Rejected

### 原因 / Cause

同事在你之前 push 了代码，远程比你的本地新：

A colleague pushed code before you, making the remote ahead of your local:

```
! [rejected] main -> main (fetch first)
```

### 解决 / Solution

```bash
# 先拉取再推送 / Pull first, then push
git pull --rebase
git push
```

`--rebase` 的作用：把你的提交"挪到"同事的提交之上，保持线性历史。

`--rebase` moves your commits "on top of" your colleague's commits, maintaining linear history.

## 四、冲突解决 / Conflict Resolution

### stash pop 冲突 / stash pop conflict

```bash
git stash pop
# CONFLICT (content): Merge conflict in xxx.java
```

处理方式 / Resolution steps:
1. 打开冲突文件，找到三段标记 / Open the conflicted file, find the three markers:
   ```
   <<<<<<< Updated upstream
   同事的代码 / Colleague's code
   =======
   你的代码 / Your code
   >>>>>>> Stashed changes
   ```
2. 决定保留哪部分（删掉另一部分和标记符号）/ Decide which part to keep (delete the other and markers)
3. `git add <文件名>` 标记已解决 / Mark as resolved

### 选择保留哪一方 / Choose which side to keep

| 命令 Command | 含义 Meaning |
|------|------|
| `git checkout --ours <file>` | 保留远程版本（丢弃本地改动）/ Keep remote version (discard local) |
| `git checkout --theirs <file>` | 保留本地版本（丢弃远程改动）/ Keep local version (discard remote) |

### .idea 文件冲突 / .idea file conflict

`.idea/` 是 IDEA 自动生成的配置，冲突了直接丢弃本地改动：

`.idea/` is auto-generated by IDEA. If conflicted, just discard local changes:

```bash
git checkout -- .idea/
```

## 七、注意事项 / Important Notes

1. **不要提交 `.idea/` 文件**：这是 IDE 配置，每个人环境不同 / Don't commit `.idea/` — it's IDE config, different per person
2. **不要提交调试用临时改动**：如 SecurityConfig 的 `permitAll()` 放行 / Don't commit debug temp changes like `permitAll()`
3. **拉取前先 stash**：养成习惯，避免冲突 / Always stash before pulling — build the habit
4. **提交前检查文件列表**：确认只提交该提交的文件 / Check file list before committing
5. **push 被拒绝不要慌**：`git pull --rebase` 再 push 就行 / Don't panic when push is rejected — just rebase and push
