## 一、网络分层模型 / Network Layer Models

### 1. OSI 七层模型 / OSI Seven-Layer Model

| 层 Layer | 名称 Name | 功能 Function | 示例 Example |
|----------|----------|--------------|-------------|
| 7 | 应用层 Application | 为用户提供网络服务 / Provide network services to users | HTTP, FTP, SMTP, DNS |
| 6 | 表示层 Presentation | 数据格式转换、加密 / Data format conversion, encryption | SSL/TLS, JPEG, ASCII |
| 5 | 会话层 Session | 建立、管理、终止会话 / Establish, manage, terminate sessions | NetBIIS, RPC |
| 4 | 传输层 Transport | 端到端可靠传输 / End-to-end reliable transport | TCP, UDP |
| 3 | 网络层 Network | 路由选择、IP 寻址 / Routing, IP addressing | IP, ICMP, OSPF |
| 2 | 数据链路层 Data Link | 帧传输、MAC 寻址 / Frame transmission, MAC addressing | Ethernet, ARP, PPP |
| 1 | 物理层 Physical | 比特传输 / Bit transmission | 电缆, 光纤, Wi-Fi |

### 2. TCP/IP 四层模型 / TCP/IP Four-Layer Model

实际开发中使用的是 TCP/IP 模型，它将 OSI 的七层简化为四层：

In practice, the TCP/IP model is used, simplifying OSI's 7 layers into 4:

| TCP/IP 层 | 对应 OSI 层 | 常见协议 |
|-----------|------------|---------|
| 应用层 Application | 5, 6, 7 | HTTP, HTTPS, DNS, FTP, SMTP |
| 传输层 Transport | 4 | TCP, UDP |
| 网络层 Internet | 3 | IP, ICMP, ARP |
| 网络接口层 Network Access | 1, 2 | Ethernet, Wi-Fi |

### 3. 一句话记忆 / One-line Memory

```
All People Seem To Need Data Processing（OSI 从下到上 / Bottom to top）
应用层 → 传输层 → 网络层 → 链路层（TCP/IP 四层 / TCP/IP 4 layers）
```

## 二、HTTP 协议 / HTTP Protocol

### 1. HTTP 基础概念 / HTTP Basics

HTTP（HyperText Transfer Protocol）是无状态、基于请求-响应的应用层协议。

HTTP (HyperText Transfer Protocol) is a stateless, request-response based application layer protocol.

**特点 Features：**
- 无状态 Stateful：服务器不记录上一次请求 / Server doesn't remember previous requests
- 基于文本 Text-based：请求和响应都是文本格式 / Requests and responses are text-based
- 默认端口 Default port：80（HTTP）/ 443（HTTPS）

### 2. HTTP 请求结构 / HTTP Request Structure

```
POST /api/v1/notice HTTP/1.1       ← 请求行 Request line
Host: localhost:8080                ← 请求头 Headers
Content-Type: application/json
Authorization: Bearer <token>
                                    ← 空行 Blank line
{"title":"公告","content":"内容"}    ← 请求体 Body
```

**请求行三部分 / Request line has 3 parts：**
1. 方法 Method：GET / POST / PUT / DELETE
2. 路径 Path：`/api/v1/notice`
3. 版本 Version：`HTTP/1.1`

### 3. HTTP 响应结构 / HTTP Response Structure

```
HTTP/1.1 200 OK                     ← 状态行 Status line
Content-Type: application/json      ← 响应头 Headers
Content-Length: 45
                                    ← 空行 Blank line
{"code":200,"msg":"success"}        ← 响应体 Body
```

### 4. HTTP 方法 / HTTP Methods

| 方法 Method | 语义 | 幂等 Idempotent | 安全 Safe | 用途 |
|------------|------|----------------|----------|------|
| GET | 查询 Read | ✅ 是 | ✅ 是 | 获取资源 / Get resource |
| POST | 新增 Create | ❌ 否 | ❌ 否 | 创建资源 / Create resource |
| PUT | 修改 Update | ✅ 是 | ❌ 否 | 全量更新 / Full update |
| PATCH | 修改 Update | ❌ 否 | ❌ 否 | 部分更新 / Partial update |
| DELETE | 删除 Delete | ✅ 是 | ❌ 否 | 删除资源 / Delete resource |

> **幂等 Idempotent**：多次调用效果和一次相同。`GET /user/1` 调 100 次结果一样。
> Idempotent: calling multiple times has same effect as calling once.

> **安全 Safe**：不修改服务器数据。GET 是安全的，POST 不是。
> Safe: doesn't modify server data.

### 5. HTTP 状态码 / HTTP Status Codes

| 分类 Category | 范围 Range | 含义 Meaning |
|--------------|-----------|-------------|
| 1xx | 100-199 | 信息响应 Informational |
| 2xx | 200-299 | 成功 Success |
| 3xx | 300-399 | 重定向 Redirection |
| 4xx | 400-499 | 客户端错误 Client error |
| 5xx | 500-599 | 服务器错误 Server error |

**常见状态码 Common codes：**

| 状态码 | 含义 | 场景 Scenario |
|--------|------|-------------|
| 200 OK | 成功 | 正常返回 / Normal response |
| 201 Created | 已创建 | POST 创建成功 / POST created |
| 204 No Content | 无内容 | DELETE 成功无返回 / DELETE success |
| 301 Moved Permanently | 永久重定向 | HTTP → HTTPS |
| 302 Found | 临时重定向 | 登录跳转 / Login redirect |
| 304 Not Modified | 未修改 | 缓存有效 / Cache valid |
| 400 Bad Request | 请求格式错误 | 参数缺失 / Missing param |
| 401 Unauthorized | 未认证 | 未登录 / Not logged in |
| 403 Forbidden | 无权限 | 已登录但无权限 / Logged in but no permission |
| 404 Not Found | 资源不存在 | URL 错误 / Wrong URL |
| 405 Method Not Allowed | 方法不允许 | GET 访问了 POST 接口 / GET on POST endpoint |
| 409 Conflict | 冲突 | 重复创建 / Duplicate create |
| 429 Too Many Requests | 请求过多 | 限流 / Rate limited |
| 500 Internal Server Error | 服务器错误 | 代码异常 / Code exception |
| 502 Bad Gateway | 网关错误 | 反向代理无法连到后端 / Proxy can't reach backend |
| 503 Service Unavailable | 服务不可用 | 维护中 / Under maintenance |
| 504 Gateway Timeout | 网关超时 | 后端响应超时 / Backend timeout |

### 6. HTTP vs HTTPS / HTTP vs HTTPS

| | HTTP | HTTPS |
|--|------|-------|
| 端口 Port | 80 | 443 |
| 加密 Encryption | ❌ 明文传输 | ✅ SSL/TLS 加密 |
| 证书 Certificate | 不需要 | 需要 CA 证书 |
| 性能 Performance | 快 | 略慢（加密开销）|
| 安全 Security | 不安全 | 安全 |

**HTTPS 握手过程 HTTPS handshake：**
```
客户端 Client                    服务器 Server
    │                                │
    │─── 1. ClientHello ──────────►│
    │    （支持的加密算法、随机数）    │
    │                               │
    │◄── 2. ServerHello ───────────│
    │    （选定算法、证书、随机数）    │
    │                               │
    │─── 3. 生成预主密钥 ──────────►│
    │    （用服务器公钥加密）          │
    │                               │
    │◄══ 4. 加密通信开始 ═══════════│
```

## 三、TCP 协议 / TCP Protocol

### 1. TCP 基础 / TCP Basics

TCP（Transmission Control Protocol）是面向连接、可靠的传输层协议。

TCP is a connection-oriented, reliable transport layer protocol.

**特点 Features：**
- 面向连接 Connection-oriented：通信前先建连 / Connect before communication
- 可靠 Reliable：保证数据不丢、不重、有序 / Ensures no loss, no duplication, in order
- 面向字节流 Byte-stream：数据以字节流形式传输 / Data as byte stream
- 全双工 Full-duplex：双方可同时收发 / Both sides can send and receive simultaneously

### 2. TCP 三次握手 / TCP Three-way Handshake

```
客户端 Client                        服务器 Server
    │                                    │
    │─── 1. SYN (seq=x) ──────────────►│
    │     "我要连接了"                    │
    │                                    │
    │◄── 2. SYN+ACK (seq=y, ack=x+1) ──│
    │     "好的，我也准备好了"              │
    │                                    │
    │─── 3. ACK (ack=y+1) ────────────►│
    │     "收到，开始通信"                 │
    │                                    │
    │◄═════ 数据传输 Data ══════════════│
```

**为什么要三次 Why three times：**
- 第一次：客户端告诉服务器"我要连" / Client tells server "I want to connect"
- 第二次：服务器告诉客户端"我准备好了" / Server tells client "I'm ready"
- 第三次：客户端确认"我知道你准备好了" / Client confirms "I know you're ready"

> 面试常问：为什么不是两次？→ 防止已失效的连接请求突然到达服务器，造成资源浪费。
> Interview: Why not twice? → To prevent stale connection requests from reaching the server and wasting resources.

### 3. TCP 四次挥手 / TCP Four-way Teardown

```
客户端 Client                        服务器 Server
    │                                    │
    │─── 1. FIN ──────────────────────►│
    │     "我发完了"                      │
    │                                    │
    │◄── 2. ACK ───────────────────────│
    │     "收到，但我还有数据要发"          │
    │                                    │
    │◄── 3. FIN ───────────────────────│
    │     "我也发完了"                    │
    │                                    │
    │─── 4. ACK ──────────────────────►│
    │     "再见"                         │
    │                                    │
    │   TIME_WAIT（等待 2MSL）            │
    │   等待 / Wait 2MSL                 │
```

**为什么要四次 Why four times：**
- TCP 是全双工的，关闭方向独立 / TCP is full-duplex, each direction closes independently
- 服务器收到客户端的 FIN 后，可能还有数据没发完 / Server may still have data to send

**TIME_WAIT 的作用 Purpose of TIME_WAIT：**
- 确保最后一个 ACK 到达对方 / Ensure last ACK reaches the other side
- 等待残留数据包消失 / Wait for lingering packets to disappear
- 持续 2MSL（最大报文段生存时间）/ Lasts 2MSL

### 4. TCP 可靠性机制 / TCP Reliability Mechanisms

| 机制 Mechanism | 作用 Purpose |
|--------------|-------------|
| 序列号 Sequence number | 保证有序 / Ensure ordering |
| 确认应答 ACK | 确认收到 / Confirm receipt |
| 超时重传 Timeout retransmission | 丢了重发 / Resend on timeout |
| 滑动窗口 Sliding window | 流量控制 / Flow control |
| 拥塞控制 Congestion control | 避免网络拥堵 / Avoid network congestion |

### 5. TCP vs UDP / TCP vs UDP

| | TCP | UDP |
|--|-----|-----|
| 连接 Connection | 面向连接 | 无连接 |
| 可靠性 Reliability | 可靠 | 不可靠 |
| 有序性 Ordering | 有序 | 无序 |
| 速度 Speed | 慢 | 快 |
| 头部 Header | 20 字节 | 8 字节 |
| 应用场景 Use case | HTTP, FTP, 邮件 | DNS, 视频, 游戏 |

## 四、IP 协议 / IP Protocol

### 1. IP 地址基础 / IP Address Basics

**IPv4 地址格式 IPv4 format：** 32 位，4 个字节，用 `.` 分隔

```
192.168.1.1
└┬┘ └┬┘└┬┘└┬┘
 8位 8位 8位 8位 = 32位 / 32 bits
```

**IP 地址分类 IP classes：**

| 类别 Class | 范围 Range | 私有地址 Private | 用途 |
|-----------|-----------|----------------|------|
| A | 1.0.0.0 ~ 126.255.255.255 | 10.0.0.0/8 | 大型网络 |
| B | 128.0.0.0 ~ 191.255.255.255 | 172.16.0.0/12 | 中型网络 |
| C | 192.0.0.0 ~ 223.255.255.255 | 192.168.0.0/16 | 小型网络 |
| D | 224.0.0.0 ~ 239.255.255.255 | — | 组播 Multicast |
| E | 240.0.0.0 ~ 255.255.255.255 | — | 保留 Reserved |

> **私有地址 Private addresses**：不在公网使用，只在局域网内部使用。
> Private addresses are used only within local networks, not on the public internet.

**特殊地址 Special addresses：**
- `127.0.0.1`：本机回环 Loopback
- `0.0.0.0`：所有网卡 All interfaces
- `255.255.255.255`：广播 Broadcast

### 2. 子网掩码 / Subnet Mask

子网掩码用来区分网络部分和主机部分：

Subnet mask distinguishes network part from host part:

```
IP:     192.168.1.100
掩码:   255.255.255.0
网络号: 192.168.1.0     ← 掩码为 1 的部分
主机号: 0.0.0.100       ← 掩码为 0 的部分

CIDR 写法: 192.168.1.100/24  ← 24 表示前 24 位是网络号
```

### 3. IPv4 vs IPv6 / IPv4 vs IPv6

| | IPv4 | IPv6 |
|--|------|------|
| 长度 Length | 32 位 | 128 位 |
| 格式 Format | `192.168.1.1` | `2001:0db8::1` |
| 地址数量 Addresses | ~43 亿 | 几乎无限 |
| NAT | 需要 | 不需要 |

## 五、DNS 域名解析 / DNS Resolution

### 1. DNS 作用 / DNS Purpose

DNS（Domain Name System）将域名转换为 IP 地址。

DNS converts domain names to IP addresses.

```
用户输入 User types: www.example.com
DNS 解析 DNS resolves: → 93.184.216.34
浏览器访问 Browser visits: 93.184.216.34
```

### 2. DNS 解析过程 / DNS Resolution Process

```
1. 浏览器缓存 Browser cache
   ↓ 未命中 miss
2. 操作系统缓存 OS cache
   ↓ 未命中 miss
3. 本地 DNS 服务器 Local DNS server
   ↓ 未命中 miss
4. 根域名服务器 Root DNS server
   ↓ 返回 TLD 服务器
5. 顶级域名服务器 TLD server（.com）
   ↓ 返回权威服务器
6. 权威域名服务器 Authoritative DNS server
   ↓ 返回 IP 地址
7. 缓存并返回 Cache and return
```

### 3. DNS 记录类型 / DNS Record Types

| 类型 Type | 含义 | 示例 |
|----------|------|------|
| A | 域名 → IPv4 | example.com → 1.2.3.4 |
| AAAA | 域名 → IPv6 | example.com → 2001:db8::1 |
| CNAME | 域名 → 域名 | www.example.com → example.com |
| MX | 邮件服务器 | example.com → mail.example.com |
| TXT | 文本记录 | 用于验证 / For verification |

## 六、面试高频问题 / Common Interview Questions

### Q1: 浏览器输入 URL 到页面显示的完整过程 / What happens when you type a URL?

```
1. DNS 解析：域名 → IP 地址
2. TCP 三次握手：建立连接
3. TLS 握手（HTTPS）
4. 发送 HTTP 请求
5. 服务器处理请求并返回响应
6. 浏览器解析 HTML
7. 加载 CSS/JS/图片等资源
8. 渲染页面
```

### Q2: GET 和 POST 的区别 / GET vs POST

| | GET | POST |
|--|-----|------|
| 参数位置 | URL 查询字符串 | 请求体 Body |
| 长度限制 | 浏览器有限制（~2KB） | 理论上无限制 |
| 缓存 | 可被缓存 | 不缓存 |
| 幂等 | 是 | 否 |
| 安全性 | 参数暴露在 URL | 相对安全 |
| 书签 | 可收藏 | 不可收藏 |

### Q3: TCP 为什么可靠 / Why is TCP reliable?

1. **序列号和确认号**：保证有序和不丢失
2. **超时重传**：发送后等 ACK，超时未收到就重发
3. **滑动窗口**：接收方告诉发送方自己能接收多少数据
4. **拥塞控制**：慢启动、拥塞避免、快重传、快恢复

### Q4: HTTP 1.0 / 1.1 / 2.0 / 3.0 的区别 / HTTP Versions

| 版本 | 关键特性 Key feature |
|------|---------------------|
| 1.0 | 每次请求新建连接 / New connection per request |
| 1.1 | 持久连接 Keep-Alive，管线化 / Persistent connections |
| 2.0 | 多路复用、头部压缩、服务器推送 / Multiplexing, header compression |
| 3.0 | 基于 QUIC（UDP） / Based on QUIC (UDP) |

### Q5: Cookie vs Session vs Token / Cookie vs Session vs Token

| | Cookie | Session | Token (JWT) |
|--|--------|---------|-------------|
| 存储位置 | 客户端 | 服务器 | 客户端 |
| 大小限制 | ~4KB | 无限制 | 无限制 |
| 安全性 | 低 | 中 | 高 |
| 扩展性 | 好 | 差（需共享 session） | 好（无状态） |
| 跨域 | 差 | 差 | 好 |

## 七、实际开发中的应用 / In Practice

### 1. 跨域问题 CORS / CORS

浏览器同源策略：协议、域名、端口必须完全相同。

Same-origin policy: protocol, domain, port must be identical.

```
http://localhost:80    → http://localhost:8080  ← 跨域（端口不同）
http://example.com     → http://api.example.com ← 跨域（域名不同）
```

**解决方式 Solution：** 服务器设置 `Access-Control-Allow-Origin` 响应头，或使用代理。

### 2. 前端代理 / Frontend Proxy

开发环境通过代理解决跨域：

Dev environment uses proxy to solve CORS:

```javascript
// vue.config.js
module.exports = {
  devServer: {
    proxy: {
      '/dev-api': {
        target: 'http://localhost:8080',  // 后端地址
        changeOrigin: true,
        pathRewrite: { '^/dev-api': '' }
      }
    }
  }
}
```

| 命令 Command | 用途 |
|-------------|------|
| `ping <host>` | 测试连通性 / Test connectivity |
| `traceroute <host>` | 路由追踪 / Trace route |
